# КАДР — переключение источников метаданных (27.10.2026)

## Реализовано в этой ветке

- TMDB сохраняется основным источником русских названий и описаний (`ru-RU`), постеров, изображений, актёров, IMDb ID и рейтинга TMDB. Переиспользована существующая реализация.
- Kinopoisk Unofficial API (`/api/v2.2/films?imdbId=...`) включён как *необязательный* дополнительный источник оценки Кинопоиска. Результат принимается только при точном IMDb ID, совпавшем годе, совместимом типе и единственном кандидате. Неполный результат не подменяет известный.
- OMDb остаётся дополнительным источником IMDb, Rotten Tomatoes и Metascore.
- ПоискКино удалён из автоматического обогащения названий/описаний/постеров; существующие методы поиска сохранены для точечного сопоставления идентификаторов к Lift, когда этот маршрут вызывается явно.
- Из `index.html` удалены встроенные TMDB-ключи. Старый локальный интерфейс настроек для ручного ввода ключей сохранён, а новое поле KPU добавлено.
- Подготовлена Netlify Function `netlify/functions/metadata.mjs` для будущей полной PWA: whitelist путей, серверные ключи, авторизация JWT аккаунта Supabase, маленький TTL-кэш. Это отдельный серверный слой **не интегрированный** с прежним статическим frontend: старый frontend не имеет полноценной серверной авторизации.

## Важные границы результата

1. Это изменение исходников, **не** развёрнутая версия. GitHub Pages/Netlify и реальные условия подключения из РФ нужно испытать отдельно.
2. Старый статический frontend после удаления встроенных секретов требует введённый пользователем личный TMDB API-токен либо последующее подключение авторизованного шлюза. Без этого живые API-вызовы там не будут работать; часть начальных карточек всё ещё отображает локальные данные.
3. Публично опубликованные ранее TMDB ключи необходимо **отозвать и выпустить новые** у владельца. Удаление из нового commit не стирает историю Git.
4. Для подключения серверного шлюза требуются `KADR_ALLOWED_ORIGIN`, `SUPABASE_URL`, `SUPABASE_ANON_KEY` и выбранные `TMDB_READ_TOKEN`, `OMDB_API_KEY`, `KPU_API_KEY`, `POISKKINO_API_KEY`. Без JWT подтверждённого аккаунта шлюз отвечает 401; без серверных настроек — 403/503. Никогда не вписывать реальные секреты в репозиторий или публичный JavaScript.
5. Кратковременный in-memory TTL-кэш Netlify не гарантирует соблюдения квот на разных cold starts. До production обязателен устойчивый лимитер/кэш, привязанный к авторизованному пользователю, и контроль расхода ПоискКино/KPU.
6. Kinopoisk Unofficial API — сторонний сервис с заявленным лимитом 500 запросов в сутки для новых аккаунтов; реальная работа, регистрация, лицензии, регион РФ и фактические лимиты нашего ключа ещё не проверены.
7. Видеоплеер Lift и его алгоритм resolve этим PR не изменяются. Ни один внешний ID не считается достаточным без отдельной проверки Lift.
8. Прямой браузерный ввод API токенов в старой PWA — временная локальная возможность; для полноценного закрытого КАДРа секреты должны храниться на сервере.

## Проверки

`node --test tests/metadata.test.mjs` — валидность KPU рейтинга, несовпадение года/типа/IMDb, неоднозначные результаты, whitelist шлюза, отказ неавторизованного доступа, отсутствие встроенного секретного токена, синтаксис inline-скриптов `index.html`.

Запрещено считать работу полностью принятой без зелёного CI, тестов на реальном подключении и настроенного backend.
